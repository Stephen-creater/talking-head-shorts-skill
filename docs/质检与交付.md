# 质检与交付

`build` 最后一步自动跑 `qa.py`，结果在 `build/qa_<名字>/`：

| 文件 | 内容 |
|---|---|
| `report.txt` | 四项检查的结论 |
| `asr.txt` | 成片重新转写（带时间），用来找漏切、重复、没字幕的话 |
| `sheet_*.jpg` | 每 2 秒一帧、13 帧一张的联系表 |

## 四项检查和通过标准

1. **规格**：1080×1920、30fps、-15±0.5 LUFS、真峰值 ≤ -1.3 dBTP。
2. **回听**：成片重新转写，和剪辑表里「应该说的话」逐字比对。
   - 一致率一般在 0.93～0.97（whisper 本身会听错几个字）。
   - 「疑似漏 / 变」逐条核对：只能是你**故意**删掉的（skip 掉的重复、keep 截掉的半句）。
   - 反方向也要查：在 `asr.txt` 里找剪辑表里没有的字。常见的是切点没切干净留下的「分三个」「不管怎么样」「意思就是说」「多的」这类碎词——用 `ths listen` 找真实边界，在那句加 `skip`。
   - 同一个短语在 `asr.txt` 里出现两次 = 重复没删干净。
3. **跳切**：实测画面切换点，1 秒内连切两次（闪帧）必须为 0。
4. **爆音**：每个人声拼接点 ±15ms 内的采样突变，必须为 0。

然后**看联系表**（程序判断不了的）：

- 有没有人出画、天花板、手挡镜头
- 字幕有没有压在举起的物品上看不清
- 图形有没有挡脸、和字幕叠在一起
- 片尾签名、结束语是否完整出现

## 交付

```bash
scripts/ths deliver $P v3
```

libx264 veryslow CRF 21、`-tune film`、AAC 160k、`+faststart`。2 分半约 50～100MB，和草稿的 SSIM ≥ 0.99（肉眼无差别），视频号、抖音、小红书都能直接传。

交付说明（写进 `out/剪辑说明.md`，也在对话里讲）：时长、结构、删了什么、哪里听不清没上字幕、配乐署名、哪些需要创作者确认。**只看了联系表、没有完整播放一遍成片的，要明说。**
